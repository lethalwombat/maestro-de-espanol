# Maestro de Español

A Spanish-tutor web app: Next.js 16 (App Router), strict TypeScript, Claude through `@anthropic-ai/sdk`.

@AGENTS.md

## Commands

- `npm run check`: task files, format, typecheck, lint, unit tests with coverage. A Stop hook runs it whenever you've changed something, and you can't end the turn until it passes.
- `npm run verify`: `check`, then a production build and the Playwright e2e tests. A task isn't done until this passes.
- `npx vitest run path/to/file.test.ts`: one test file. Use it while iterating; save `check` for the end.
- `npx playwright test e2e/file.spec.ts`: one e2e file. It builds the app first, so it takes about a minute.
- `npm run evals`: the LLM evals, against the real API. They cost money, so ask before running them. Required when a prompt, an output schema or `src/lib/llm/` changes (see /run-evals).
- `npm run tasks`: tasks and their status.

## How work happens here

- Every change belongs to a task spec in `tasks/`. Specs are human-owned: writing or editing one asks the user. No spec for the work? Ask the user, or draft one with /new-task.
- Work happens on a `task/<id>-<slug>` branch. Edits and commits on `main` are blocked.
- Keep notes in `progress/<id>-<slug>.md`: plan, log, decisions, discoveries, evidence. After compaction or `/clear`, the SessionStart hook re-injects the task's objective and scope.
- Start with `/start-task <id>`. Finish with `/finish-task`, which goes through @docs/definition-of-done.md.

## Judgment calls (no hook enforces these, so they're on you)

- Do what the acceptance criteria ask, and stop there. Unrelated bugs, refactors and ideas go under "Discovered" in the progress file, not into the diff.
- If a criterion is ambiguous or can't be met as written, stop and ask. Don't reinterpret the task.
- Write the failing test first and watch it fail, then write the code.
- When a check fails, fix the cause. Never skip, delete or loosen a test, assertion, lint rule or threshold to get green. If you think one is wrong, say so.
- Report what you verified with the command and its output, not "tests pass".

## Conventions

- A feature lives in `src/features/<feature>/`, with its logic, prompt, schema, UI and tests side by side. `src/app/` stays a thin routing layer.
- Every Claude call goes through `src/lib/llm/`. Model, effort and fallbacks are set once in `config.ts`, and `requestStructured()` handles refusals, truncation and invalid output. Unit tests use `fakeAnthropic()` from `src/lib/llm/testing.ts`. Real network access is blocked in unit tests.
- Validate anything from outside with zod: request bodies, LLM output, API responses in the browser.
- Use `@/` imports in `src/`. Harness code under `harness/` runs directly on Node, so it uses relative imports with `.ts` extensions.

## Gotchas

- The harness (`.claude/`, `harness/`, `.github/` except `.github/workflows/deploy.yml`, `.githooks/`) and the tool configs that define the gates are human-owned, and edits to them are blocked. If one needs to change, tell the user what and why. docs/harness.md explains every guardrail.
- `next dev` rewrites the Next.js block in AGENTS.md. Commit it as it is.
- `LayoutProps` and `PageProps` are generated by `next typegen`, which `npm run typecheck` runs first.
- The first e2e run needs a browser: `npx playwright install chromium`.
